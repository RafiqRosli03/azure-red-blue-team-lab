SCREENSHOT GUIDELINE — Phase 11-13: Attack -> Detect -> Investigate -> Respond
================================================================
This is the richest phase for evidence. Capture the FULL STORY of each exercise so a reader
sees the attack happen AND the defender catch it. Below is the set for the SQLi exercise;
repeat the same pattern for each later exercise (IDOR, etc.).

--- MILESTONE (do this once) ---
  [ ] 0. The proof the log pipeline works: the ContainerInstanceLog_CL query result showing
         the full Apache line with KIRO_LOGTEST_001 + source IP + User-Agent.
         FILE: phase11-00-logpipeline-proof.png

--- A) ATTACK (from Kali) ---
  [ ] 1. Baseline request-count query (BEFORE the attack) — the "normal" number.
  [ ] 2. Manual injection ' OR '1'='1 returning multiple rows (injectable proof).
  [ ] 3. sqlmap --dbs output (databases enumerated).
  [ ] 4. sqlmap -T users --dump output (credential table dumped) — the impact shot.

--- B) DETECT (in Sentinel) ---
  [ ] 5. Payload-signature KQL + results (UNION/SELECT/OR 1=1 hits).
  [ ] 6. sqlmap User-Agent KQL + results.
  [ ] 7. Volume-spike KQL + timechart showing the burst vs baseline.

--- C) INVESTIGATE ---
  [ ] 8. Timeline KQL (first probe -> enumeration -> dump, in order).
  [ ] 9. Source-IP attribution (10.20.2.4 = Kali).
  [ ] 10. AzureActivity pivot-check (no control-plane escalation).

--- D) RESPOND ---
  [ ] 11. Containment action (az container stop, or NSG rule tightened).
  [ ] 12. Hardening note (parameterized queries / WAF / raised security level).
